# Atlas SLSA Provenance

This document describes the Atlas SLSA provenance workflow and how reviewers
verify build provenance for Atlas release artifacts.

## Build Provenance

The release SLSA workflow is defined in `.github/workflows/release-slsa.yml`.

### Pinned Actions

- `actions/checkout@v6` pinned to `de0fac2e4500dabe0009e67214ff5f5447ce83dd`
- `actions/attest@v4` pinned to `59d89421af93a897026c735860bf21b6eb4f7b26`

### Workflow Properties

The release SLSA workflow must include:

- Checkout with full history and tags (`fetch-depth: 0`, `fetch-tags: true`)
- Release commit resolution with `${GITHUB_SHA}^{commit}` for annotated tag
  compatibility
- Tag-triggered release builds must verify the tagged commit matches
  `origin/main`
- Tag-triggered release builds must run QA from a local `main` branch tracking
  `origin/main`
- Local Atlas QA with `nix-shell --run './bin/dev-qa'`
- Strict v1 readiness with `nix-shell --run './tools/atlas/bin/atlas v1 status --strict'`
- Release artifact creation from `git archive` at `$ATLAS_RELEASE_COMMIT`
- SHA-256 checksum generation
- Contents manifest generation from the release artifact tarball
- Path-level artifact boundary check that rejects runtime-state directories and
  forbidden sensitive path markers before upload
- Artifact upload
- `actions/checkout`, `cachix/install-nix-action`, `actions/upload-artifact`,
  and `actions/attest` pinned to immutable commit SHAs
- `actions/attest@v4`
- `subject-path` pointing to the generated release artifact
- Required permissions:
  - `contents: read`
  - `id-token: write`
  - `attestations: write`
  - `artifact-metadata: write`

### GitHub Artifact Attestations

`actions/attest@v4` generates a SLSA build provenance attestation for the
release artifact. The attestation binds the artifact to the tagged commit,
the workflow run, and the build environment.

## Verification

Reviewers can verify provenance offline or online:

- Offline: `gh attestation verify <artifact>.tar.gz --repo rodriguezaa22ar-boop/atlas-trust-infrastructure`
- Online: `gh attestation verify <artifact>.tar.gz --repo rodriguezaa22ar-boop/atlas-trust-infrastructure --online`

## Retained Reference

A retained SLSA reference for atlas-v0.4.0-rc1 is stored at
`docs/retention/releases/atlas-v0.4.0-rc1.slsa.json`. It records:

- Artifact path and SHA-256
- Source commit and ref
- Workflow run URL
- Attestation URL and verification status
- Official SLSA generic provenance

## Atlas Verifier

The Atlas verifier command is `atlas release slsa-verify <reference>`. It
checks retained SLSA provenance references and supports local artifact
verification and optional online attestation checks.

## Not External SLSA Certification

This is not external SLSA certification. The retained reference records
real artifact evidence for a specific build, but does not certify the broader
build system or claim production approval. Verification confirms the artifact
matches the retained metadata; it does not certify the entire supply chain.

## External SLSA Certification

External SLSA certification is not claimed by this retained reference. The
reference records real artifact evidence for a specific build, but does not
certify the broader build system or claim production approval.

## Official SLSA Generic Provenance

For release artifacts built outside the Atlas SLSA workflow, Atlas supports
verification of official SLSA generic provenance generated by
`slsa-framework/slsa-github-generator/.github/workflows/generator_generic_slsa3.yml@v2.1.0`.

The generic provenance path is defined in `.github/workflows/release-slsa-generic.yml`.

Reviewers can verify official SLSA generic provenance with
`slsa-verifier verify-artifact`.

## Tagged Commit Matches

Tag-triggered release builds must verify that the tagged commit matches
`origin/main`. If the tagged commit does not match `origin/main`, the release
build must fail before producing any artifact.

## Local Main Branch Tracking

Tag-triggered release builds must run QA from a local `main` branch tracking
`origin/main`. This ensures the release artifact is built from the exact commit
that was tagged and reviewed.
